# 07 · Architecture decision register (proposed: none approved)

| ID | Decision | Alternatives | Trade-off | Status |
| --- | --- | --- | --- | --- |
| **G-1** | Canonical key encoding 2 = `to_json(array(CAST(normalised part AS STRING) …))`. NULL = JSON null. Comparison stays by normalised string | Native struct keys; length-prefix; typed serialisation; hash-only | Injective, Spark-native, readable, string-compatible with every current use. Wider keys (05). Typed serialisation would break the intended cross-layer string comparison; struct keys would require retyping a stored column, which migrations cannot do | Proposed |
| **G-2** | A normaliser that turns a non-NULL raw part into NULL makes the key **unparseable**: unassessable (ledger), UNASSESSABLE (release 1). Unparsed downstream rows never satisfy a key | Treat unparseable as NULL (today); drop silently | Implements the model's "unparseable key"; fails closed. A false FAIL is possible where the pipeline legitimately nulls a bad date (it is then an exclusion to declare) | Proposed |
| **G-3** | The version is determinable only when **every** row of the key (before the cutoff) has a usable record time; otherwise unassessable. An untimed key's due load is its latest load | The latest *valid* time (today); a fallback to load time | No silent drop. A key with an old garbage row stays unassessable until the data is fixed (the false-FAIL burden is measured by the new counts) | Proposed |
| **G-4** | The labels carry the reason only (`no record time`, `unparseable record time`, `tied rows disagree: …`); the counts `(n of m rows)` go into the scope | Counts in the label | Bounded label cardinality in `dq_reconciliation` against at-a-glance counts. Recommend counts in the scope | Proposed (choose) |
| **G-5** | Tied rows must **agree** on a deletion or exclusion (MIN = MAX); otherwise `unassessable 'tied rows disagree: …'`. Rows each covered by *some* approved exclusion count as excluded (combined label; every listed rule's guard counts it) | Any row (MAX, today); winner_rule resolution | Fixes F-07 without changing the approved value-tie rule | Proposed |
| **G-6** | Rejects: a total order (time, then defect before authorised, then reason, then rule) | `max_by` on time only (today); unassessable on any tie | Deterministic and fail closed; no new outcome | Proposed |
| **G-7** | `dq_key_event.key_encoding` (migration 2) plus a self-healing transition (a forced sweep and closing events), preceded by preparatory release N (the writer tolerates migration-added columns) | A bridge (dual encodings in every evaluation); sniffing a prefix in `key_value`; rewriting stored rows (forbidden) | Forward-only and auditable, with no stored row changed. A one-off sweep cost; a rollback path via release N | Proposed |
